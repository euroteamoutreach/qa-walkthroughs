What this PR fixes Uploaded report photos used to intermittently throw a 500 (a Postgres foreign-key violation) or show broken images / 404s, because the background optimizer purged a photo's original blob while the page was still generating a thumbnail of it. Photos now render only once they're optimized; until then they show a brief "processing" placeholder that auto-swaps to the real thumbnail.

Part 2 — The “processing” placeholder and live auto-refresh new in this PR

In dev, optimization finishes in about a second, so the placeholder is normally just a flash. To watch it deliberately, toggle the very flag the display gates on, from a console.

  1. Open a Rails console:
  2. Clear the optimized marker on the photo you just uploaded, then reload the report page in the browser: 
    # the most-recently-touched report that has photos — your upload
report = EventReport.where.associated(:photos_attachments).distinct.order(updated_at: :desc).first
blob = report.photos.first.blob
blob.update!(metadata: blob.metadata.except("optimized"))
    ✅ The photo is now a placeholder: a pulsing clock icon, the “Обробка…” text, and a “Завантажити оригінал” link. In devtools → Network you'll see the page quietly refetch itself every ~2s.
  3. Click Завантажити оригінал (Download original).
    ✅ The original image opens/downloads — the fallback that keeps a not-yet-optimized photo reachable.
  4. Back in the console, restore the marker — and this time do not reload the browser: 
    blob.update!(metadata: blob.metadata.merge("optimized" => true))
    ✅ Within ~2s the placeholder auto-swaps to the real thumbnail on its own, no manual reload — and the polling stops once no placeholders remain.

Not browser-testable
⏱️
The actual race — a thumbnail request for the original blob colliding with the optimizer purging it (the FK-violation 500 / 404) — is a timing race you can't trigger by clicking. In-browser you confirm its absence; the race is covered by the controller test (no representation URL is emitted for an un-optimized photo) and the system tests.
🔁
The poller's give-up cap (~60 polls) is a bounded background safeguard for a photo that never finishes optimizing — not practical to observe in a short session.
