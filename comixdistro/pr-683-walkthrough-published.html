Not browser-testable
  • The status-code → file mapping (a real 422 or 500) is wired by Rails' ActionDispatch::PublicExceptions, not by this PR's code. Triggering a genuine 500/422 needs a deliberately-broken route. A real 404 was confirmed to serve our page with a 404 status; 422/500 use the identical mechanism.
  • Graceful degradation of the CSS toggle on very old browsers (falls back to Ukrainian) can't be exercised in a modern browser.
Cleanup
  • If you did Part 4, make sure the consider_all_requests_local flag is reverted.
