Walkthrough
Part 1 — Eager upload, accumulation & remove-before-submit new in this PR
  1. Sign in as (see Setup).
    ✅ You land on the home page showing the active Kharkiv event with a CTA to finish / edit the report.
  2. Open the report's edit form — click the finish report CTA on the home page, or open the Kharkiv event and click Редагувати звіт (Edit report).
    ✅ The form shows a Narrative field and an Завантажити фотографії (Upload photos) file picker. No thumbnail grid yet.
  3. Click the file picker and choose one photo.
    ✅ A thumbnail tile appears immediately with a dark progress overlay; the bar fills and the overlay is replaced by a green check badge (Завершено / Complete). The Save/Submit buttons are disabled while the upload is in flight, then re-enable.
  4. Open the picker again and choose a different photo (a separate pick session).
    ✅ The second photo is added as a new tile — the first is NOT replaced. (This is the core fix: previously only the last batch survived.)
  5. On one completed tile, click the × button (top-right).
    ✅ That tile disappears; the other remains. The removed photo will not be attached on submit.
  6. Click Зберегти чернетку (Save draft).
    ✅ Redirects to the report view showing the remaining photo(s); the count reads e.g. "1 з 10 фотографій" (1 of 10 photos).
  7. Optional — force a failed upload: re-open the edit form, open DevTools → Network → set throttling to Offline, then pick a photo.
    ✅ The tile shows a red Помилка (Failed) state, no hidden photo is attached, and the × lets you remove it. Set Network back to Online and re-pick — it uploads cleanly.
Part 2 — Accumulation alongside saved photos & the 10-photo guardrail new in this PR
  1. From the saved report, click Редагувати звіт (Edit report) again.
    ✅ The photo you saved in Part 1 now appears under Поточні фотографії (Current photos) with a Видалити (Remove) checkbox — the persisted-photos path.
  2. Pick several more photos.
    ✅ New tiles upload and accumulate below the current photos, independent of them.
  3. Keep picking until existing + new would exceed 10 (e.g. with 1 saved photo, select 10+ new ones at once).
    ✅ Once the cap is reached, an inline red message appears: "Можна додати щонайбільше 10 фотографій." (You can attach up to 10 photos.) and the over-limit file gets no tile. The first ten still upload.
  4. Tick a Видалити (Remove) checkbox on a Current photo, then pick one more new photo.
    ✅ It's accepted — the client counts existing − removals + new against the cap, so freeing a slot lets one more in.

Not browser-testable
🧹
Recurring orphan-blob sweep (PurgeUnattachedBlobsJob) — purges abandoned unattached uploads older than 2 days. It's a production-only SolidQueue schedule (daily at 3am); verified by a job unit test, not in the browser.
📏
The 25 MB / JPEG-PNG client guardrails are easy to see but awkward to trigger: the picker's accept filter hides non-images, and a >25 MB test image is a hassle to source. The server validations remain authoritative and are covered by model + controller tests.
Cleanup
