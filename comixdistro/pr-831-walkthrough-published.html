Part 1 — Admin attaches, then stays on the report (re-entry) new in this PR

Signed in as admin@example.com.

  1. Open the photo-help queue: .
    ✅ The list includes a request from Київська книжкова місія.
  2. Click that request's event title (or «Прикріпити фото»).
    ✅ The assist form «Прикріпити фотографії» opens, showing the distributor's narrative and a file picker.
  3. Click the file input, choose a photo, wait for the pending tile to read «Завершено», then click «Прикріпити фотографії».
    ✅ NEW: you land back on this same assist form — not the queue list — with a green notice: «Фотографії прикріплено — Київська книжкова місія отримав сповіщення для перегляду та подання. Потрібно додати ще? Прикріпіть нижче або поверніться до черги.» The photo shows under «Поточні фотографії — 1 з 10 фотографій».
    ✅ NEW: the attached photo resolves from its «Обробка…» placeholder to a real thumbnail on its own within a few seconds — no manual reload.
    ↩︎ Before this PR you were bounced to the queue with no path back, and the newest photo hung in «Обробка…».
  4. Attach a second photo the same way (choose file → «Завершено» → «Прикріпити фотографії»).
    ✅ Photos accumulate across rounds: the count reads «2 з 10 фотографій», each with a «Видалити» checkbox.
  5. Click «← Допомога з фото» (the back-to-queue link on the form).
    ✅ You return to the queue and the Київська книжкова місія request is gone (its flag cleared when you first attached).

  1. Open the report you just helped with — (use the event N from the Setup snippet; usually 1).

    ✅ The panel switches to the pending state — a blue notice «Ви попросили допомогти з прикріпленням фото…». The acknowledgment and re-request button are gone (the report is back in the "requested" state).

Not browser-testable
  • MAX_PHOTOS enforced across rounds. Reaching the 10-photo cap by accumulation and being rejected on the 11th is impractical to click through — covered by controller tests.
  • Per-round activity logging. Each admin attach records a photos_attached_by_admin entry and each distributor round records a photo_help_requested entry; verified in tests rather than surfaced in the UI.
  • Poll doesn't clobber a pending removal. The admin form's photo grid pauses its auto-refresh while a «Видалити» box is checked, so a background refresh can't reset an unsubmitted removal; covered by a system test.
