Part 2 — Onboarding completes with JavaScript disabled new in this PR

This is the fix — in two halves. (1) The button is no longer permanently dead when JS fails, so a user like Oleksandr isn’t trapped. (2) The server now enforces consent, so a no-JS user still can’t skip the boxes — an empty submit bounces back with an error instead of sailing through. You’ll exercise both.

  1. Open DevTools (), open the Command Menu (), type Disable JavaScript, press Enter. Leave DevTools open so JS stays disabled.
    ✅ A warning badge appears; JavaScript no longer runs on the page.
  2. Sign up with , then click the magic link that opens.
    ✅ You land on onboarding Step 1 (magic-link sign-in works without JS).
  3. Complete Step 1 (Profile) and Step 2 (Organization) — plain forms, never JS-gated.
    ✅ You reach Step 3 — Distributor commitments.
  4. Half 1 — not trapped: look at the «Продовжити» button before ticking anything.
    ✅ It is fully blue and clickable — NOT greyed out. (Before this PR it was permanently disabled here, trapping the user.)
  5. Half 2 — can’t skip consent: with no boxes ticked (or only some), click «Продовжити».
    ✅ The page reloads on Step 3 with a red error banner («Будь ласка, підтвердіть кожне зобов’язання, щоб продовжити.» / “Please acknowledge every commitment to continue.”). You do not advance. Any box you had ticked stays ticked.
  6. Now tick all the boxes and click «Продовжити».
    ✅ You advance to Step 4. Repeat through Step 5 (each step bounces an empty submit, advances a complete one).
  7. On Step 6 — Final acknowledgment, first click «Завершити реєстрацію» with the box unticked.
    ✅ It bounces back with an error and onboarding is not completed.
  8. Tick the acknowledgment box and click «Завершити реєстрацію».
    ✅ You land on the home page with the success message — onboarding completed end-to-end with JS disabled, consent intact.
  9. Re-enable JS: Command Menu () → Enable JavaScript.
Not browser-testable
  • The brief enable→disable flash (JS on). With JS present the button renders momentarily enabled before the Stimulus controller disables it on connect(). Too fast to observe reliably; cosmetic only.
  • Consent timestamp. Completing acknowledgment stamps terms_accepted_at / terms_version on the distributor — confirmed by tests and the /verify run, not visible in the UI. (The new server check means this is stamped only when the box was actually ticked.)
  • The exact rejection logic (which keys are required per step, the 422 status) is covered by integration tests; the browser shows the user-facing half — the error banner and staying put.
